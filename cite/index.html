Current citation guidance

Until the first formal Atlas release is published, cite the repository as an evolving research software/data resource and include an access date. If your result depends on a particular Atlas state, also record the Git commit SHA.

Provisional citation:
Alhaj Hasan, A. F. PINN Review Atlas. GitHub repository and interactive research atlas, 2026. Available at: https://github.com/ahafuaej-alt/PINN-Review. Accessed: [date].

Planned reproducible release

The first formal publication/reproducibility snapshot is planned as v2026.09.1. This Atlas-level release identifier is separate from component dataset versions such as the Master Bibliography and PINN Realm version 2.3.1 and Frameworks version 3.0.0.

After the release is archived, this page will provide both the version-specific archival DOI for the exact v2026.09.1 snapshot and the persistent concept DOI for the evolving PINN Review Atlas. No DOI has been assigned yet.

How to cite reproducibly

Atlas as a wholeCite PINN Review Atlas using the repository citation metadata and, after formal release, the DOI.
Exact research stateRecord the Atlas release identifier or exact Git commit SHA used for the analysis.
Specific Atlas resultLink to the narrowest relevant page, figure, table, formulation, paper profile, comparison, or dataset view rather than only the Atlas home page.
Downloaded materialKeep the originating page URL and release/commit identifier with exported CSV, JSON, SVG, PNG, or other derived files.
Component dataWhere relevant, retain the component dataset version or snapshot date in addition to the Atlas-level release identifier.

Machine-readable citation

The repository includes a root CITATION.cff file. GitHub uses this metadata to provide its Cite this repository interface. The file currently identifies the repository as unreleased; immediately before the formal release it will be updated to v2026.09.1 with the release date, and DOI metadata will be added after archival.

Release policy

Atlas releases follow the date-based convention vYYYY.MM.N. Each formal release is intended to resolve to an immutable Git tag and exact commit SHA so that a published result can be reconstructed from the same repository state. See RELEASE.md ↗ for the complete release and reproducibility policy.
