## 1. Purpose and hard boundary

Task 6.5 answers two related but distinct questions:

> Which of the 36 Task-6.4 residual XPD pairs require blocking, guarded recovery, or redirection rather than ordinary comparison?

and

> Which analytical operations are invalid or scientifically misleading even when the selected XPD pair itself is otherwise meaningful?

The controlling distinction is:

**pair admissibility ≠ operation admissibility ≠ scientific inference ≠ UI availability.**

A pair of dimensions is not declared scientifically invalid merely because an unsafe operation can be performed on it. Conversely, a Task-6.4-approved pair does not make every possible operation scientifically valid.

Task 6.5 therefore formalizes two layers:

1. **residual-pair disposition** for the 36 pairs intentionally left unresolved by Task 6.4; and
2. **operation-level hard blocks and misleading-inference guards** applicable across the complete comparison surface.

Task 6.5 does **not** create the Task 6.6 machine-readable comparison-choice map and does **not** design Task 6.7 UI/routes.

## 2. Residual-pair disposition classes

Task 6.5 uses four possible pair-level disposition classes.

- **`I` — intrinsically invalid as a generic scientific comparison.** No ordinary or guarded pairwise analysis is scientifically defensible without changing the scientific question into a different governed relation/path.
- **`M` — misleading by default.** The pair is hidden/disabled from ordinary scientific comparison because the most obvious interpretation invites ecological, quality, superiority or performance inference. A narrowly framed meta-research audit may still be defensible with explicit safeguards.
- **`K` — conditionally recoverable through a narrower governed comparison.** The generic pair is not authorized, but a specific scoped record/linkage question is valid when its exact join, unit, denominator and non-inference warning are declared.
- **`R` — redirect / redundant with a better governed path.** Generic pairwise comparison is the wrong mechanism; the requested information must be obtained from an existing owner, scope/support relation or curated object instead.

### 2.1 Important scientific conclusion

After reviewing the 36 residual pairs, Task 6.5 finds **0 pair-level `I` cases**.

This is deliberate, not an omission. The scientific defect in these residuals is not that the two dimensions can never coexist in a legitimate research question. The defect is that an ordinary generic pairwise comparison either:

- invites a misleading inference (`M`);
- requires a much narrower governed linkage (`K`); or
- duplicates a more scientifically correct owner/path (`R`).

Hard invalidity is therefore concentrated in the **operation-level catalogue** in Section 5, where the prohibited transformation or inference can be stated precisely.

## 5. Operation-level invalid / misleading catalogue

The following rules apply regardless of whether the selected pair is `D`, `C`, `L7`, `M`, `K` or `R`.

Two severities are used:

- **`HB` — hard block:** the requested computation/transformation/inference is scientifically invalid under current Atlas governance and must not execute as stated.
- **`MG` — misleading unless guarded:** descriptive computation may be possible, but the interpretation/display must carry explicit constraints and must not imply the forbidden inference.

### 5.1 Hard-block operations — `HB-01..HB-26`

| ID | Invalid operation | Required treatment |
|---|---|---|
| `HB-01` | Substitute global `N = 853` for a dimension's governed eligible denominator | Use the declared dimension/pair-specific eligible population |
| `HB-02` | Treat paper, record, assignment, result, relation, evidence, collaboration edge or PEU/study-family counts as interchangeable | Preserve and label the actual analytical unit |
| `HB-03` | Multiply N:M assignments across two dimensions to manufacture a Cartesian sample size | Use unique-paper presence or an explicit scoped relation/link |
| `HB-04` | Treat paper co-membership as proof that two records refer to the same experiment/problem/task/claim/test case | Require the governed scoped linkage |
| `HB-05` | Count multiple statements/publication versions/components from one study family as independent recurrence for the same question | Apply Task-5.5 study-family/PEU anti-inflation rules |
| `HB-06` | Collapse `missing`, `not reported`, `reported unavailable`, `not applicable`, `unresolved` or equivalent governed states into scientific absence/negative evidence | Preserve the governed state explicitly |
| `HB-07` | Compare percentages/rates from materially different eligibility populations as though they share one denominator | Declare separate denominators or restrict to a justified common population |
| `HB-08` | Collapse `XPD-25` metric identity and `XPD-26` metric result/test-case observation into one variable | Preserve metric identity versus observation/result ownership |
| `HB-09` | Numerically pool/order incompatible metric definitions, units, scales or optimization directions | Restrict to semantically compatible metric definitions and direction |
| `HB-10` | Pool/rank quantitative results across unmatched test cases, baselines, boundary/initial conditions, data regimes or evaluation contexts | Require matched evaluation context (`CM-05`) |
| `HB-11` | Mix paper-level summaries, test-case observations and repeated/aggregate result levels as if independent observations | Preserve aggregation level and dependence |
| `HB-12` | Convert author claim into demonstrated result | Retain claim/demonstration distinction and explicit evidence link |
| `HB-13` | Convert a generality/transfer claim into evidence of generality/transfer | Require demonstration/evidence appropriate to the claimed scope |
| `HB-14` | Merge contribution/innovation with outcome/degree of resolution | Preserve separate owners and links |
| `HB-15` | Merge physical problem, computational task and PINN challenge because terms co-occur | Preserve all three governed dimensions |
| `HB-16` | Treat parent `XPD-17 Methodology` as one pooled categorical variable or calculate a generic methodology frequency | Select a governed child owner/facet first |
| `HB-17` | Infer an `XPD-36` typed scientific relation from co-occurrence | Require an explicit governed relation instance |
| `HB-18` | Infer reverse relation direction or symmetry when the relation registry does not define it | Use only governed directionality/cardinality |
| `HB-19` | Apply an evidence/source/support label from one record to unrelated records merely because they share a paper | Join evidence to its governed target record/scope |
| `HB-20` | Treat verification status, semantic support status and statement strength as the same property | Preserve orthogonal evidence/integrity semantics |
| `HB-21` | Treat evidence-object count, citation count or repeated mentions as independent scientific support | Use study-family/PEU or other declared independence unit where independence is claimed |
| `HB-22` | Promote an L6 frequency/association/recurrence signal directly into an official `XPD-37` gap or `XPD-38` opportunity | Require governed Level-7 curation and Task-5.5-compatible evidence review |
| `HB-23` | Treat limitation, open problem or future-work frequency as an official Atlas research gap/opportunity | Preserve source-level dimensions and separate Level-7 synthesis ownership |
| `HB-24` | Combine taxonomy/ontology/normalization versions as if labels and meanings were identical without version reconciliation | Declare versions and use governed mappings/migrations |
| `HB-25` | Export a comparison while stripping denominator, unit, scope, eligibility, evidence/provenance, version or warning qualifiers needed to interpret it | Qualified export only |
| `HB-26` | Mix publication year, review/search window, extraction date, verification date or other temporal semantics as one time variable | Select and label the intended temporal owner/semantic before analysis |

### 5.2 Misleading-unless-guarded operations — `MG-01..MG-09`

| ID | Misleading interpretation | Required guard |
|---|---|---|
| `MG-01` | Frequency/prevalence interpreted as evidence strength, importance or scientific truth | Label as corpus prevalence only; expose evidence strength separately |
| `MG-02` | Association/co-occurrence interpreted as causality, effect size or method superiority | Label as descriptive association; causal/effect claims are prohibited absent an appropriate design/evidence basis |
| `MG-03` | Geographic, institutional or collaboration prominence interpreted as scientific quality, validity, rigor or impact | Label as bibliographic/context distribution only |
| `MG-04` | Group-level geographic/institutional/collaboration pattern projected onto individual papers, methods or researchers | Explicitly prohibit ecological inference and retain individual scientific evidence |
| `MG-05` | Temporal increase/decrease interpreted automatically as methodological progress, improvement or deterioration | Describe observed corpus trend only; no causal/progress claim |
| `MG-06` | Publication venue/source context interpreted as a scientific-quality score | Treat source context as bibliographic metadata, not validity/quality evidence |
| `MG-07` | Absence of recorded contradiction interpreted as consensus or truth | Report only “no contradiction recorded under current evidence,” preserving coverage limits |
| `MG-08` | Sparse or highly imbalanced strata ranked without sample-size/coverage disclosure | Show counts/denominators and suppress/qualify unstable ranking |
| `MG-09` | Collaboration-edge, affiliation, evidence-object or relation-event counts interpreted as unique papers/studies/independent supports | Display the actual unit and, where relevant, the corresponding unique-paper/study count separately |

## 6. Pair-status does not override operation guards

Examples:

- A `D` pair can still be invalid if executed with `HB-03` Cartesian inflation.
- A `C` pair cannot bypass its scoped join by using a paper-level cross-tab.
- An `L7` pair remains read-only and cannot bypass `HB-22`/`HB-23`.
- An `M` pair is not made safe merely by adding a warning if the requested computation itself violates an `HB` rule.
- A `K` pair is executable only through its documented narrow recovery path.
- An `R` pair must redirect to the governed owner/path rather than emulate a generic comparison.
